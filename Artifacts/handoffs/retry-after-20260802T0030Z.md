## The defect

`RetryPolicy` is titled "Jittered exponential backoff with **Retry-After** support
(FR-TRN-012)" and `delayNanoseconds(attempt:retryAfterSeconds:)` implements it correctly.
But the only call site passed `nil`:

```swift
let delay = retryPolicy.delayNanoseconds(attempt: attempt - 1, retryAfterSeconds: nil)
```

and nothing in the tree ever captured the header — `DMCurlHeaderCtx` collected
content-type, etag, last-modified, accept-ranges, content-disposition and content-range,
but not retry-after. The documented capability did not exist end to end.

It matters on these hosts: they do return 429. Answering on our own backoff curve instead
of the server's means coming back early, earning another refusal, and spending one of only
`maxAttempts` (8) whole-job attempts on it.

## The change

Plumbed through every layer it has to cross:

1. **C** — `DMCurlHeaderCtx.retryAfter` captured in the header callback beside
   accept-ranges; freed in `DMCurlHeaderCtxClear`; ownership transferred to
   `DMCurlDownloadResult.retryAfter` at both population sites; freed in
   `DMCurlDownloadResultClear`.
2. **`TransferError.httpStatus`** gained `retryAfterSeconds: Double?` **with a default**, so
   every construction site compiles unchanged and only the four pattern matches needed
   updating. The delay belongs on this case because it is a property of the status
   response, and the retry path is the only consumer.
3. **`TransferCore.retryAfterSeconds(_:)`** parses it.
4. **`CurlMultiLoop.MultiError.httpStatus`** carries it so the segmented path is covered too,
   not just single-stream.
5. **`TransferOrchestrator.handleFailure`** binds and passes it.

### Delta-seconds only, on purpose

The HTTP-date form is legal but rare from rate limiters, and misreading a date as a number
is worse than ignoring the header: falling back to our own backoff costs seconds, while a
wrong parse could park a job for hours. `RetryPolicy` already clamps to 3600 s, so a
hostile header cannot park a job either.

## Verification

`Tests/Unit/RetryAfterParsingTests.swift` — delta-seconds, whitespace, HTTP-date, garbage,
negatives, infinities, and that the policy prefers the server's delay over its own curve
while still clamping.

`Tests/Integration/RetryAfterIntegrationTests.swift` — the header surviving the whole
journey, on new fixtures `/fixtures/rate-limited` (429 + `Retry-After: 7`) and
`/fixtures/rate-limited-http-date`.

**Confirmed red first.** The parser being correct proves nothing if the header never
arrives, so the C capture was temporarily broken (matching `"x-never-matches"` instead of
`"retry-after"`) and the suite re-run:

```text
testDeltaSecondsReachesTheThrownError: XCTAssertEqual failed:
  ("nil") is not equal to ("Optional(7.0)")
testHTTPDateFormLeavesTheDelayUnset  passed
testAbsentHeaderStaysNil             passed
```

Only the positive test failed — the two negative tests stayed green, so they were not
passing vacuously. Capture restored, all three green.

`FaultHTTPServer.send` gained an optional `headers:` parameter, emitted in sorted order so
a fixture's bytes are identical run to run.
