## Engine defects found and fixed

1. **The speed limit did nothing on the default path.** The only
   `SyncBandwidthGovernor` was built inside `downloadSingleStream`; `CurlMultiLoop`
   — the transport for every download ≥1 MiB — never referenced it. The Dispatch
   fallback was wrong the other way: one full-rate bucket per segment, ~32× the cap.
   Now one governor per job fed the ledger's aggregate count, per-segment caps
   stripped. Regression test: 1.6 s where the unthrottled path took 0.02 s.
2. **FTP/SFTP were accepted and then guaranteed to fail.** `isPhase1Supported`
   allows them and libcurl is built with FTP + libssh2, but `probeRangeSupport`
   demanded HTTP 200/206 — FTP returns 226/250, SFTP returns 0. Every such link
   failed once with a bogus `networkUnavailable`. Added `CurlURL.isHTTPFamily`;
   non-HTTP schemes take the single-stream path and a scheme-appropriate status gate.
3. **Tile cap abandoned the anti-straggler property at scale.** 128 tiles meant a
   4 GiB file used 32 MiB chunks and a 40 GiB file 320 MiB chunks — one slow
   connection owning a quarter-gigabyte. Cap is 1024; chunks hold the 4 MiB floor
   out to 4 GiB. `SegmentTilingTests` asserts this at sizes a suite cannot download.
4. **`checksumMismatch` went through the retry path** — resuming the same partial
   from the same `.segmap` and rehashing the same bytes three times. Now terminal;
   Restart (which wipes the partial) is the user-driven recovery.

## Features delivered

- **Checksum verification**, previously a dead path calling `IntegrityVerifier`
  against a column hard-coded to `nil`. Plumbed Add sheet → XPC → engine with a
  shared `ChecksumFormat.normalizedSHA256`, decoder failing closed, schema v4.
- **Per-download speed limit and connection count**, clamped by the socket budget in
  both directions — a 2-connection job now reserves 2 instead of hogging 32.
- **Browser integration on community installs.** The native host connected only via
  `machServiceName`, which the ad-hoc heal path deliberately unregisters — it was
  dead on the install the README advertises. Now falls back to `downloadmanager://`
  resolved from the host's own bundle. Header channel v2 (allowlisted, re-validated,
  never logged; `Cookie` dropped for multi-URL batches). Install script derives the
  extension ID instead of requiring a hand-pasted one.
- **Shortcuts / App Intents** — 5 intents, all through `EngineClient` over XPC. This
  is the scriptability AB DM gets from a localhost REST API, without opening a port.
- **Homebrew cask written** (not published — needs a tap repo and a sha256 verified
  against the published asset).
- **`CLAUDE.md` + `.claude/`** — path-scoped rules, a `verify-scope` skill, a
  `transfer-performance` agent, a hot-path hook, MCP and permissions.

## Deliberately NOT done

- **Safe-zone tail-stealing.** AB DM splits the tail off a *live* part because their
  downloader owns the stream. Flow hands libcurl a fixed `Range:`, so the equivalent
  means aborting a connection mid-flight from the C write callback and reconciling
  the short read against the `.segmap` — and the split belongs at the ledger layer,
  not inside `CurlMultiLoop`, which receives a fixed `[RangeRequest]` and reports by
  index. That is a protocol change with file-corruption blast radius. Finer tiling
  bounds what a straggler costs; it cannot take back work already in flight.
- Undo for row removal (needs XPC surface to resurrect deleted rows).
- Manual VoiceOver pass — still the open item it was two releases ago.
- Torrent / media / notarization — ADR 0006 / ADR 0008.

## Caveats that must not be buried

- **SwiftLint never ran.** `make lint` prints `swiftlint not installed; using grep
  safety backstop` and passes on the backstop. Every green in this session covers
  SwiftFormat, the build, tests and the banned-token scan — not the strict rule set.
  CI is the first real check.
- **The browser path was never exercised end to end** — no Chrome, no installed app,
  no engine. It compiles and its unit tests pass; that is not the same as working.
- **Headers still cannot reach a transfer on a community install unless Flow is
  already running.** Putting a session cookie in a LaunchServices URL would be a
  credential leak; closing this needs a hand-off file through `OpenURLIngest`.
